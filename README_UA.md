# Мисливські господарства Волині: 26 років даних про дику природу — пайплайн, аналіз і застосунок

*[Read in English → README.md](README.md)*

Аналіз динаміки популяцій диких тварин на мисливських угіддях **Волинської області, Україна (2000–2025)** методами машинного навчання, тепер розгорнутий як інтерактивний застосунок. Проєкт складається з трьох частин: **(1) пайплайн обробки даних**, що перетворює 26 років неоднорідних державних звітів на один чистий аналітичний датасет, **(2) ML-моделі** (прогнозування часових рядів, регресія, класифікація, кластеризація, детекція аномалій), результати яких перевірені на реальних історичних подіях, і **(3) Streamlit-застосунок**, що поєднує виводи моделей з чат-інтерфейсом на базі LLM для запитів до тієї самої бази даних.

> **Коротко для рецензентів.** Найскладнішою частиною були не моделі, а дані. П'ять різних форматів звітності за 26 років, **184 по-різному названі сутності зведено до 75 канонічних угідь**, зміни одиниць виміру (га ↔ тис. га), і "чорна дірка" у звітності під час реформи Лісового агентства 2023 року. Моделі свідомо консервативні: там, де сигналу в даних не було (VAR хижак-жертва, прогноз по кабану), модель **відхилялась, а не форсувалась**. Головна знахідка: заборона полювання 2022 року пов'язана з **+18.9% відновленням популяції козулі** до 2025 року.

## Частина 1 — Пайплайн обробки даних (справжня робота)

Державна Форма 2-ТП подавалась по-різному в п'ять різних епох. Один парсер не пережив би їх усіх, тож пайплайн використовує **п'ять специфічних для формату парсерів**, що живлять спільну схему:

```
сирі .xls / .xlsx  (5 епох форматів)
        │
        ▼
┌──────────────────────────────────────────────┐
│  old_format.py    2000–2012  (стейт-машина)   │
│  mid_format.py    2013–2017                    │
│  hybrid_2018.py   2018  (перехідний рік)       │
│  new_format.py    2019–2024                    │
│  new_2025.py      2025  (найновіший формат)    │
└──────────────────────────────────────────────┘
        │  → processed/*.csv  (по роках)
        ▼
  build_final.py   — мапінг сутностей 184 → 75, канонізація видів
        │
        ▼
  data/final/*.csv  — чистий аналітичний датасет
```

**Чому п'ять парсерів.** Формати справді різняться, а не косметично:
- **old (2000–2012):** угіддя — це *колонки*, види — це *рядки*; Розділ III потребує **стейт-машини**, щоб відстежувати поточний вид крізь підрядки.
- **mid (2013–2017):** угіддя стають рядками; популяції на окремому листі `облік`; відстріл у жорстко заданих діапазонах колонок.
- **2018 (гібрид):** метадані/фінанси як у *mid*, але метрика `expense_breeding` й листи переселення як у *new*, площі ще в гектарах. Рік, що не підходить під жоден окремий парсер.
- **new (2019–2024):** лист `8. ОП користувачів`, площі в тисячах га, розділи знаходяться **пошуком за ключовими словами**, а не фіксованими індексами.
- **2025:** новий макет листа `Чисельність`, види у двох підколонках; автор помилково підписав одиницю площі (написав га під заголовком "тис. га") — парсер **виявляє й виправляє** це (÷1000).

**Рішення щодо надійності, важливі для рецензування:**
- Розділи знаходяться за ключовим словом (`find_section_columns`), а не магічними номерами колонок, тож зсув колонки не ламає парсинг мовчки.
- `is_invalid_host()` прибирає забруднення, знайдені в реальних даних — номери телефонів і прізвище оператора звіту, що потрапляють у поле угіддя.
- Рядки-підсумки ("усього", "по області", "разом") відфільтровуються, щоб підсумки ніколи не рахувались двічі.

|-------|------|-------|---------|----------------|

| harvest | 2,365 | 55 | 44 | 338 козуль відстріляно (38 угідь) |
| hosts_meta | 495 | 55 | — | — |

Назви угідь виходять чистими й канонізовними (`Городоцьке ЛГ`, `Горохівське ЛМГ`), лапки нормалізовані, рядки оператора/підсумків прибрані.

### Якість даних — розкрита, а не прихована

Пайплайн видає розріджені таблиці, і це відкрито заявлено, а не замасковано:

| Таблиця (2018) | Валідних | NaN | NaN % |
|--------------|-------|-----|-------|
| hosts_meta | 357 | 138 | 27.9% |
| finances | 203 | 182 | 47.3% |
| populations | 1,103 | 1,317 | 54.4% |
| harvest | 319 | 2,046 | **86.5%** |

**Чому harvest порожній на ~86% — і чому це очікувано.** Harvest — це матриця 55 угідь × 44 види (2,420 клітинок), але лише кілька видів реально відстрілюються на будь-якому конкретному угідді. Більшість пар угіддя×вид легітимно порожні ("нічого не відстріляно"). Перевірено вибірково: козуля показує реальні цифри по угіддях (5, 13, 6, 9, 12 …), качки 7,449, заєць 4,264 — парсер читає правильні клітинки, матриця просто розріджена.

**Відоме обмеження (чесно).** Порожня клітинка трактується як нуль, але справжній `0` ("відстріляно нуль") і "не звітувало" в джерелі однаково збігаються в `NaN`, і їх неможливо розрізнити. Навіть козуля має 17/55 таких клітинок. Це властивість вихідних даних, тут задокументована як реальне обмеження метрик на основі harvest.

## Частина 2 — Моделі

Кожне рішення в моделюванні продиктоване доменною реальністю, а не гонитвою за метриками.

### Ключова знахідка 1 — заборона полювання 2022 року спрацювала (+18.9% козуля)
На 18 угіддях з неперервною звітністю 2019–2025:

| Період | Популяція | vs базовий рівень |
|--------|-----------|-------------|
| 2019–2021 базовий рівень | 2,865 | — |
| 2022 (початок заборони) | 2,903 | +1.3% |
| 2025 | 3,408 | **+18.9%** |

Прогноз 2026–2028: **3,576 (консервативний тренд) → 4,286 (агрегований ARIMA)**. *Стійкість результату:* ширша вибірка угідь дає +17.4% на прямому порівнянні 2022→2025; тренд до заборони (2015–2021) був практично рівним, тобто це не існуюче раніше зростання.

*Реалізовано як: вкладка **Time Series** — рахується лише для козулі й кабана; решта трьох фокусних видів не мають достатньо неперервної історії звітності для змістовного прогнозу, тож цифра для них свідомо не форсувалась.*

### Ключова знахідка 2 — детекція аномалій самостійно перевідкрила кожну важливу подію
Isolation Forest, **без жодних закодованих подій**, відмітив топові аномалії, що збігаються з реальною історією: падіння кабана на −89% до −98% (2019–2020 = Африканська чума свиней), стрибки +200% до +667% у 2023 (угіддя відновлюють звітність після реформи), ВЕСТА М +1678% у 2022 (перший звіт нової приватної ферми). Незалежна перевірка проти реальних подій — найкраща доступна перевірка для методу без учителя.

*Реалізовано як: вкладка **Anomaly Detection**, по видах (Кабан, Козуля, Лось, Олень благородний), кожен з графіком розподілу score і прикладами по угіддях.*

### Ключова знахідка 3 — угіддя діляться на три групи, без чіткої середньої ланки
K-Means (k=3, підтверджено і методом ліктя, і силуетним методом) розділяє угіддя на: невеликий кластер-аутлаєр з коротким терміном звітності або різко спадаючою популяцією, середньобюджетний давно існуючий кластер, і високобюджетний давно існуючий кластер. *Застереження:* `n_years` є ознакою кластеризації, тож поділ частково відображає стабільність звітності, а не лише фізичний/фінансовий розмір; дві показані PCA-компоненти пояснюють лише ~63% загальної варіації.

*Реалізовано як: вкладка **Кластеризація**, з обґрунтуванням через elbow/silhouette поруч із результатом.*

### Методи та цілісність підходу

| Скрипт | Що робить | Рішення щодо цілісності |
|--------|--------------|------------------|
| `time_series.py` | прогноз `auto_arima` по угіддю | автовибір порядку (не жорстко заданий ARIMA(1,1,0)); `STABLE_HOSTS` генерується автоматично; MAE 16.8 (козуля) / 25.9 (кабан) на трейні 2000–18 / тесті 19–21 |
| `regression.py` | прогноз популяції + SHAP по інвестиціях | **`TimeSeriesSplit`** (без витоку майбутнє→минуле); чесний негативний результат — фінанси слабко прогнозують зміну популяції |
| `classification.py` | класифікатор стійкості відстрілу | **`TimeSeriesSplit`** (див. виправлення нижче); `StandardScaler` усередині `Pipeline`; `class_weight='balanced'` |
| `clustering.py` | типологія угідь (K-Means + PCA) | k за силуетом+ліктем; Державний резерв виключений як доменний аутлаєр (утворював вироджений одиночний кластер, силует 0.78) |
| `anomaly_detection.py` | детекція подій Isolation Forest | `contamination` лише задає поріг відсікання — **не** впливає на `score_samples`, тож ранжування аномальності однакове для 0.02/0.05/0.10; перевірено проти реальних подій, а не самореферентної метрики стабільності |

**Нюанс щодо графіків регресії:** лінія популяції в графіках `regression.py` — це *середнє значення на одне звітне угіддя*, а не сумарна цифра по області (на відміну від вкладки Time Series, яка сумує фіксовану стабільну підмножину з 24 угідь). Обидва числа коректні й чесні — вони просто відповідають на різні питання — і застосунок явно це підписує, щоб дві вкладки не виглядали суперечливими.

#### Чесне виправлення — крос-валідація класифікації
Класифікатор спочатку використовував `StratifiedKFold(shuffle=True)`, що перемішує роки і дозволяє моделі вчитись на майбутніх даних, щоб передбачати минулі — витік, від якого решта проєкту явно захищається. Перехід на **`TimeSeriesSplit`** (трейн завжди строго до тесту) дає чесну картину:

| Вид / модель | Leaky F1 (перемішування) | Чесний F1 (часовий) | Завищення |
|-----------------|-------------------|---------------------|-----------|
| Козуля / Random Forest | 0.73 | **0.57 ± 0.20** | +0.16 |
| Кабан / Random Forest | 0.63 | **0.40 ± 0.20** | +0.23 |
| Кабан / Logistic Regression | 0.69 | **0.64 ± 0.13** | +0.05 |

Із цього виправлення випливають дві знахідки: (а) витік коштував до **0.23 F1** — майже чверть метрики; (б) при чесній крос-валідації саме *простіша* модель (Logistic Regression) краще узагальнюється в часі, тоді як Random Forest найбільше виграла від витоку. Для козулі два з п'яти часових фолдів **не мають жодного позитивного прикладу** (усі 24 випадки "надмірного відстрілу" припадають на пізні роки), тож класифікатор по козулі **недостатньо підтверджений даними** — це заявлено як обмеження, а не як результат.

*Реалізовано як: вкладка **Класифікація**, лише козуля й кабан (два види з достатньою кількістю даних про відстріл, щоб модель мала сенс).*

## Частина 3 — Інтерактивний деплой (Streamlit)

Робочий застосунок має **6 вкладок**: чат-інтерфейс і по одній вкладці на кожну модель вище.

**Вкладка чату.** Дворівневий LLM-пайплайн над базою SQLite, через безкоштовний Groq API:
1. **Виклик розпізнавання** (`openai/gpt-oss-120b`) — розбирає довільне питання на структуровані поля (вид, угіддя, тема, сирі дані чи аналіз), маючи в контексті *реальний* список видів/угідь із бази, щоб зіставляти синоніми й альтернативні написання.
2. **`rapidfuzz`** — другий, детермінований шар, що робить нечітке зіставлення розпізнаних назв виду/угіддя з реальними значеннями бази, ловлячи все, що LLM не зіставив точно.
3. **SQL-запит**, побудований під тему (population / harvest / finance / staff / relocation, або всі п'ять одразу).
4. **Виклик аналізу**, теж `openai/gpt-oss-120b` — перетворює сирі числа на текстовий опис тренду. *(Спочатку тут використовувалась менша/швидша модель; замінено після того, як виявилось, що вона робить базові помилки в обчисленні відсотків при підсумовуванні багаторічних трендів — відома слабкість малих моделей у числовому міркуванні, не проблема промпту.)* Цей виклик також отримує задокументований доменний контекст — заборону полювання з 2022 року, повномасштабну війну (з лютого 2022) і спричинену нею "чорну дірку" в звітності через реформу Лісового агентства 2023 року, а також Африканську чуму свиней конкретно коли питання про кабана — щоб модель пояснювала тренди реальними задокументованими причинами, а не вигадувала їх чи мовчала.

**Вкладки моделей.** Кожна з п'яти вкладок моделей (Кластеризація, Регресія, Класифікація, Anomaly Detection, Time Series) показує збережені графіки плюс письмовий висновок *та* обмеження для кожного результату — той самий стандарт чесності, що й у цьому README, а не просто графік без інтерпретації.

**Технічні нюанси реалізації:**
- З'єднання з SQLite обгорнуте в `@st.cache_resource` (з `check_same_thread=False`), щоб пережити модель "перезапуск скрипта на кожну взаємодію" Streamlit без перепідключення чи падінь між потоками.
- Ключ Groq API читається через `st.secrets`, повністю поза git (і `.env`, і `secrets.toml` у `.gitignore`); задається локально через `.streamlit/secrets.toml`, а в хмарі — через дашборд Streamlit Cloud.
- Працює на безкоштовному тарифі Groq — без витрат за поточного навантаження, хоча безкоштовний тариф має денний ліміт запитів/токенів на модель, про який варто знати, якщо трафік зросте.

## Запуск

**Моделі / пайплайн даних:**
```bash
pip install -r requirements.txt

# 1. розпарсити + зібрати датасет
python build_final.py

# 2. запустити будь-яку модель (види — опційні CLI-аргументи)
python models/time_series.py Козуля Кабан
python models/classification.py
python models/clustering.py
python models/anomaly_detection.py
```

**Веб-застосунок (локально):**
```bash
streamlit run app.py
```
Потребує `.streamlit/secrets.toml` з `GROQ_API_KEY = "..."` (безкоштовний ключ — на console.groq.com).

## Технічний борг (чесно)
- Словники `metrics_hosts_meta` / `metrics_finances` дублюються в чотирьох парсерах; мають бути в одному конфігу (зараз зміна формату означає редагування чотирьох файлів).
- `mid_format.py` використовує жорстко задані діапазони колонок (напр. `(124,181,"shot_heads")`) — прийнятно для замороженого історичного формату, але структурний ризик, якщо ці файли колись перевипустять.
- `build_final.py` мовчки відкидає немаповані угіддя; варто виводити немаповану множину перед фільтрацією.

## Обмеження
- Звітність за 2023–2024 неповна через реформу Лісового агентства (враховано явно, включно з контекстом, вбудованим у чат).
- Прогнози — це **тренди**, а не точні цифри, і рахуються лише там, де вихідні дані достатньо неперервні (2 з 5 фокусних видів для Time Series, 2 з 5 для Класифікації).
- Порожнє значення й "не звітовано" нерозрізнимі в harvest (обидва `NaN`).
- Прогноз по кабану свідомо відсутній через волатильність АЧС.
- Зіставлення синонімів видів покладається лише на `rapidfuzz` (без ручного словника синонімів); ловить варіанти написання, але не справжні діалектні синоніми.
